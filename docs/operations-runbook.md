# נוהל תפעול - מקום לזכור

עודכן ב־13.10.2026. אחראי: הראל ארונוביץ׳. הגרסה הפעילה וראיות השחרור נקבעות ב־[רשומת ההמשך](agent-handoff.md), לא משם תיקיית build. אין קישורי מעקב, סודות, כתובות או תוכן פניות ביומן אירוע או ב־Git.

## בדיקה שוטפת והתראות

- GitHub availability: שבע GET ללא סודות/עוגיות, פעם בשש שעות UTC בדקה23, וגם הפעלה ידנית; HTML/CSP, version/feed וארבעה נתיבים פרטיים. publication handoff אחד מותר; אין retry לשגיאת שרת או כתיבה. job עד שתי דקות, בלי npm ci. תזמון GitHub עשוי להתעכב; אינו SLA או זיהוי מיידי. ארבע הרצות ביום, דקות וחיוב לפי התוכנית והמשך בפועל, ללא הרחבת תקציב.
- כשל Actions מופיע ב־GitHub. המפעיל צריך לוודא קבלת מייל על workflow failure בהגדרות GitHub. אין טענה להגעת הודעת כשל לפני הוכחה.
- Cloudflare: שתי התראות10USD קיימות נשמרו; אלה התראות ולא hard cap. test של מדיניות התקציב הקיימת התקבל200 והראל אישר קבלה בתיבה ב־13.10. usage מפורט נחסם בהרשאות הנוכחיות, שלא הורחבו.
- runtime issues: מדיניות enabled לכתובת המפעיל, עצמאית מה־Gmail API של האתר. test החזיר שגיאה פנימית; הגעה טרם אומתה. השירות אינו מבטיח זיהוי כל כשל או השבתה מלאה של Cloudflare.
- מוני /api/ops ומסך המנהל פרטיים ומדוגמים. לוג חדש mail_delivery_failed שומר רק outcome קבוע; mail_budget_unavailable מציין חסם מסד. אין provider error, גוף או capability בלוג. מכסה צפויה אינה runtime error; גם מטא־דאטה אינו אישור להגעת מייל.
- security.yml: audit וסריקת סודות שבועית; compatibility.yml: בדיקת דפדפנים שבועית. אינם מבחן חדירה חיצוני.

## טיפול באירוע

1. רשום UTC, גרסה/ריצה, סוג והיקף ידוע/לא ידוע; בדוק endpoint חי ומצב ספק רשמי. אין הסקת תקיעה מתאריך בלבד.
2. בחשד לחשיפה, בעל המערכת מחליט על עצירת כתיבה/פרסום דרך ההגנה הקיימת, שומר Access snapshot ומבודד את הנתיב. לא פותחים wildcard או מורידים אימות כדי לבדוק.
3. שמור לוג קודים מוגבל וראיות; בלי MIME, סוד, גוף פנייה או קישור. בדיקת תיבה מוגבלת להודעה הנחוצה והמותרת.
4. Gmail: בדוק OAuth, stopped/uncertain והגעה למכסה ב־ops. אין resend לא ודאי, fallback relay או העלאת gmail.modify לאתר. פנייה שנכשלה אינה מבטיחה מסירה; אימות פועל במסלול הניסיונות הבטוחים הקיים.
5. סוד שנחשף מבוטל/מוחלף בידי בעל המערכת; אין scope חדש או מחיקת ראיות. מעריכים אם לבטל יכולות מעקב שנפגעו.
6. המפעיל מעריך דיווח לרשות/נפגעים לפי הדין והאירוע, בעזרת גורם מתאים. לא שולחים בשמו הודעות לצד שלישי ללא אישור. מיישמים תיקון ובדיקה ממוקדת לפני חזרה.

## rollback ושחרור

מפרידים תקלת קוד מתקלה בנתונים/ספק. לא משחזרים מסד עבור באג UI. ב־Cloudflare Versions בוחרים גרסה קודמת רק לאחר התאמת source/receipt, bindings/secrets והתאמה למיגרציות. rollback קוד אינו rollback נתונים ואינו ביטול הסרות.

שינוי חדש דורש בדיקות ממוקדות, CI full וכיסוי ראשון מדויק, staging אוטומטי באותוSHA עם תשע pass וחבילת production מול ענן/Access טריים. אין סודות בבנייה או deploy עוקףCI. רשומת deploy כוללת hash קבצים, SHA, CI/staging, version/tag, הגרסה הקודמת וקריאת תוצאה חיה.

אחרי פריסה: version, פיד רענן, גבולות פרטיים, תמונה/OG, טופס נגיש ומנהל. שינוי דואר דורש הודעת בדיקה אחת ליעד הפרויקט והגעה נצפית. הוספה/אישור/משיכה נבדקות בדמה עם הצהרות ואישור מחיקה ממוקד; לא בנתוני אדם אמיתי. אין חזרה על תרגילי שחזור שכבר נסגרו כשמחזור החיים לא השתנה.

## גיבוי ומפתחות

export מוצפן, ledger וסינון שחזור ל־DRILL_DB נפרד אומתו תפעולית ב־11.10. קצב קיים: תחזוקה15 דקות, export23h, drill שבועי. snapshot ידני תחום אינו מאפס cadence. לא מוחקים רשומות הצלחה ולא משניםcreated_at/ceiling/guards כדי לכפות בדיקה.

לפני שחזור: export המוצלח האחרון ונקודת המחיקה האחרונה; רק החדש ביותר והטרי במסגרת החסם. סינון תפוגה/ledger קודם לכתיבה לתרגול, שמירת מועדים ובדיקת suppression לפני חזרה. מנקים תרגול לפי התהליך המאושר. Time Travel מוקדם אינו תחליף. אובדן עדכונים מאז הגיבוי נרשם.

מפתח בעלים אינו עולה לענן. נדרש עותק מוגן מחוץ למחשב עם יכולת שימוש במקרה כשל; זמינותו טרם אושרה. קודי MFA נשמרים בידי המפעיל, לא בצ׳אט. נעילת R2 אינה הוכחת שחזור בלי המפתח או מחיקה פיזית.
