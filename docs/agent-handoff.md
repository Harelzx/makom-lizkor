Name the independent task first. One heavy browser suite at a time (`scripts/heavy`). The runner records checkout, full commit, dirty files, each stage's command and real exit status (`meta.txt`, `summary.tsv`), and a JSON timing report per browser stage (`<stage>-timing.json`).
- Measure before optimizing: the required full runs give the timings (`timing.py`, `compare-timing.py`); then small, justified changes (skip the opening in unrelated backend specs, observable conditions instead of sleeps, controlled time for timer logic). Keep real-browser coverage of reloads, storage, multiple tabs and the critical journeys; keep the frame-rate checks separate. Never drop assertions, mock the behavior under test, or retry until green. Report measured savings only.
- A pass applies to the commit tested; later changes are integrated and their impact checked before a merge.
