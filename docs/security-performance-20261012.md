# תיקוני אבטחה וביצועים לאחר ההשקה

הראל אישר ב־12.10.2026 את כל תיקוני הדוח ואת פריסתם לאחר בדיקות. הבסיס הוא main45f5779 והגרסה הציבורית eb2441e. מצב העבודה והראיות נמצאים ב־`../agent-evidence/security-performance-20261012/implementation-progress.json`; מסמך זה מתאר את המימוש, ולא טוען שגרסה חדשה כבר נפרסה.

## גבולות שאינם משתנים

- הנתונים החיים, הסתרות והסרות נקראים מהמסד. `EDGE_CACHE=off`; API ונתיבים פרטיים נשארים no-store, ומדיה ציבורית מוגבלת לדקה. רק קבצי build בעלי hash תחת `/assets/` מקבלים immutable לשנה; HTML מתעדכן בבדיקת רענון. שער הבילד מסרב לקובץ בלתי מזוהה בנתיב המטמון.
- Access והמנהל הקיים, audience, הסודות, מסדי EU, הצפנת הגיבוי וה־ledger נשמרים. אין רכישה, שירות תמונות נוסף, scopes נוספים או שינוי בלוח הגיבויים והמחיקה. אין תרגיל שחזור הרסני חוזר.
- “כתבו לנו” ממשיך לשלוח ישירות לתיבה בלי מסד, outbox או retry אוטומטי. מנגנון מסירת האימות משתמש רק במטא־נתונים של contact שכבר נשמר; בלי גוף הודעה, עותק נוסף של כתובת או token גלוי. מחיקה ותפוגה מפסיקות אותו.

## מה משתנה

1. מגבלות bytes אמיתיים לפני JSON/multipart, גם בזרם בלי Content-Length אמין, וספירת בקשות מוקדמת. התקציבים נפרדים: JSON24KiB, אימות/מחווה1KiB, פנייה12,000bytes ותמונת הצעה5MiB לבקשה/4MiB לקובץ. הרשאת תמונה נבדקת לפני קריאתה. הקריאות הציבוריות מוגבלות240 לדקה לרשת המבקר, בספירה תחת HMAC. המגבלה של Cloudflare היא מקומית למיקום ולא מכסה כספית גלובלית.
2. תחום contact נוסף לאחר נרמול IPv6; כתובות באותו /64 נספרות יחד והיעדים נשארים נפרדים.
3. CSP אכוף, עם wasm-unsafe-eval רק לצורך מקודד התמונות המקומי; JavaScript eval וסקריפט inline אינם מותרים. ה־sandbox של תמונות נשמר. נדרשות בדיקות תכונות ו־CSP בדפדפן וב־staging לפני production.
4. Cloudflare toolchain מתעדכן לגרסה הכוללת sharp0.35.5. shadcn CLI ו־patch-package מוסרים כדי להוציא braces שלא תוקן upstream; ה־CSS מורשה MIT מועתק בלי שינוי והתיקון הקודם של Vaul מוחל תחת בדיקות hash/version. נוסף npm audit, סורק פורמטים מוכרים של credentials שאינו מדפיס ערכים, Dependabot וסריקה שבועית. זו אינה הוכחה שכל סוד אפשרי או חולשה עתידית יזוהו.
5. שאילתת מדיה מתחילה באינדקסי keys וממשיכה בבדיקת revision שפורסם עכשיו והסתרות פעילות. נוספים שני אינדקסים בררניים עבור pending ו־contacts. SCAN של feed מלא אינו “מתוקן” באינדקס חסר תועלת.
6. הגלריה קוראת רק את התמונה הנוכחית ושכנתה, ותמונות אחרות lazy. גדלי640/960 נוצרים דרך WASM במאגר הקיים, בהרכב המלא, בלי להחליף מקור או thumbnail חתוך. URL המקור נבדק לפני ואחרי יצירה; הנתיב הישיר של קובץ נגזר אינו נפתח. גודל פיקסלים נבדק לפני decode, ורק יצירה אחת בכל isolate מתבצעת במקביל; בקשה נוספת מקבלת מקור תחת אותם שערים. נגזרות נמחקות עם המקום, נסרקות כחלק ממחזור חייו ואינן דורשות העתק נוסף בגיבוי - הן נוצרות מחדש מהמקור.
7. קבלת הצעה נענית אחרי העסקה במסד, בלי להמתין ל־Gmail. מסירת אימות מופעלת ב־waitUntil וב־cron הקיים, עד חמישה ניסיונות בטוחים במרווח15 דקות ובתוך תוקף ה־contact/link. טוקן אימות נגזר ב־HMAC ונשמר רק hash שלו. מסירה ללא תשובה ודאית אינה נשלחת שוב אוטומטית; גם שחזור אינו משחזר לשליחה פעילה מצב שעלול כבר להישלח. הודעות על דיווח אינן מעכבות את receipt. תקציבי לקוח מתאימים לגבולות siteverify/ספק הקיימים.
8. מכסת דואר אטומית בכל החשבון:230 ניסיונות ציבוריים ביום UTC ועוד20 שמורים להתראות. זהו גבול לאתר, לא מדידת מכסת Gmail הכוללת שימוש ידני. דחייה בגלל המכסה אינה מוציאה ניסיון ספק. הדואר נשאר הטקסט הקבוע וההרשאה gmail.send בלבד.
9. דגימה עצמאית1/32 של בקשות Worker שומרת רק שעה, status, מספר דגימות וזמן/ספירת תגובות איטיות. אין כתובת, path, query, גוף, מפתח מעקב או זהות; אין מונים בגיבוי. המונים מתנקים בסבב הרגיל לאחר כשני ימים, עם גרנולריות השעה/התזמון. דוח /api/ops ומסך מנהל מוגן מסמנים במפורש שהספירות מדוגמות. אין דגימה של קבצים סטטיים או של בקשות ש־Access חסם לפני ה־Worker. תקלות/מסירות לא ודאיות/התקרבות למכסה מדווחות בערוץ ההתראות הקיים, לכל היותר סבב מוצלח ביום. כשל Gmail אינו יכול להבטיח התראת Gmail; מצב המנהל נשאר דרך עצמאית לקרוא את המונים.

תקרת CPU לכל invocation מוגדרת במפורש30,000ms, בהתאם לברירת המחדל הקיימת ל־HTTP ול־cron בתדירות של15 דקות. לא הורדנו את התקציב המשותף ל־5 שניות בלי מדידה נפרדת של עבודות ההצפנה/הגיבוי; תיעוד Wrangler מתאר מגבלה לכל invocation, ולא מגבלת fetch נפרדת. הנתונים שנקראו ב־12.10:126 invocations, אפס errors בדוח, P50=35.844ms, P99=89.920ms ו־P99.9=279.273ms; יחידות השדות אושרו ב־GraphQL introspection כ־microseconds. אלה מדידות גרסה קודמת ודגימה של הספק, לא benchmark של התיקון או הבטחת חיוב. לפני השלמת rollout יש לבדוק בפועל raster/OG ו־cron והמדידה החדשה. אין שינוי בתדירות ה־cron, cadence או guards של הגיבוי.

## אימות ופעולה אנושית

נדרשים בדיקות לוגיקה/Worker/סקריפטים, תכונות ו־WebKit רלוונטיות, CI full באותו SHA, staging אוטומטי עם תשע pass, בדיקת חבילת production מול snapshot טרי ושמירת הגישה הציבורית/הנתיבים הפרטיים. רק אז פריסה ואימות חי של הוספה, אישור ודואר בדמה תחומה. בדיקות מחזור החיים המקומיות אינן תרגיל ייצור חדש או הוכחת מחיקה פיזית.

בדיקת API של חשבון הראל החזירה MFA כבוי. הראל בחר להפעיל אותו בהמשך; אינו מסומן כפתור. אין שינוי חד־צדדי של שיטת הכניסה או של גורם האימות. זו פעולה פתוחה נפרדת. אין הבטחה שאתר כלשהו “לא פריץ”.

מסך כרטיס מוגבל ל־640/960 במערך srcset גם בצפיפות3x; מקור נשאר src fallback ואינו מאבד איכות במאגר. לא מצהירים על רוחב1600 קבוע למקורות שגודלם משתנה. מבחן WebKit חשף את בחירת המקור הגדולה והראיות נשמרו לפני התיקון.
