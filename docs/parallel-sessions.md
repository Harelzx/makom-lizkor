# עבודה מקבילית עם כמה סשנים

כמה סשנים של Claude Code יכולים לעבוד על הריפו הזה בבת אחת, כל אחד ב-worktree משלו. שני מנגנונים שומרים עליהם:

1. **נעילה לפקודות כבדות.** e2e, Playwright, build, `npm ci` ורינדור סרטים רצים רק דרך `scripts/heavy`, אחת בכל רגע, ורק כשיש למחשב מקום.
2. **יומן אבני דרך.** כל מיזוג ל-`main` נרשם ביומן משותף, וכל סשן מקבל בהקשר שלו רק את מה שחדש לו.

הכול נאכף ב-hooks שב-`.claude/settings.json`, לא בשיקול הדעת של הסוכן.

## איך זה עובד

**מצב משותף.** כל המצב יושב ב-`.git/claude-parallel/` של הריפו הראשי, שכל ה-worktrees חולקים. שום דבר לא נכתב לעץ העבודה. מה שיש שם:

| קובץ | מה הוא |
| --- | --- |
| `heavy.lock/owner.json` | מי מחזיק את הנעילה: worktree, branch, פקודה, PID ושעת התחלה |
| `milestones.jsonl` | היומן. שורה לכל אבן דרך: זמן, branch, סיכום ותיקיות שהשתנו |
| `read/<key>.offset` | עד איפה כל worktree קרא ביומן |
| `watch.json` | הקומיט האחרון ב-`main` שכבר נרשם, כדי שמיזוג לא יירשם פעמיים |
| `ports.json` | מספר ה-slot של כל worktree, שממנו נגזרים הפורטים שלו |

**`scripts/heavy <command>`:**

1. אם סשן אחר מחזיק את הנעילה, מדפיס מי, מה רץ וכמה זמן, ויוצא עם קוד 75 בלי להריץ.
2. בודק עומס: load ממוצע לדקה וזיכרון פנוי. אם המחשב עמוס, מחכה ובודק שוב כל 10 שניות עד 5 דקות, ומראה מה צורך משאבים. אם העומס לא ירד, יוצא עם 75.
3. תופס את הנעילה באופן אטומי עם `mkdir`, מריץ את הפקודה, ומשחרר בכל סוף: הצלחה, שגיאה או Ctrl-C.
4. נעילה שהתהליך שלה מת נמחקת אוטומטית בהרצה הבאה.

**ה-hook שלפני Bash** בודק כל פקודה מול `.claude/heavy-commands.txt`. פקודה כבדה שלא עוברת דרך `scripts/heavy` נחסמת, והסוכן מקבל הודעה להריץ אותה דרך העטיפה.

**יומן אבני הדרך:**

- בתחילת סשן ובכל הודעה שלך, בודקים אם `main` (ו-`origin/main`, אם יש remote) התקדם, ורושמים רשומה לכל מיזוג חדש. מיזוג `--no-ff` נרשם כרשומה אחת, ו-fast-forward נרשם כרשומה אחת לכל הקומיטים שנכנסו יחד.
- כשיש remote, `git fetch` רץ ברקע לכל היותר פעם ב-5 דקות, ואף פעם לא מעכב hook.
- `scripts/milestone "טקסט"` מוסיף רשומה עשירה יותר מכותרת של קומיט.
- סשן חדש מקבל את 5 הרשומות האחרונות. אחרי כל הודעה ואחרי כל כלי, הוא מקבל רק רשומות שעוד לא ראה, ולא את אלה שהוא עצמו כתב. כשאין חדש, לא נוסף כלום להקשר.

**פורטים לכל worktree.** ה-checkout הראשי שומר על 5174 (dev), 5190 (e2e ו-preview) ו-4174 (prod e2e). כל worktree מקבל slot משלו: 5400+n, 5500+n, 5600+n. ה-hook של תחילת הסשן כותב לו `.claude/launch.json` על הפורט שלו, ולכן ה-preview וה-e2e שלו לא נוגעים אף פעם בשרת של worktree אחר. בלי זה, `reuseExistingServer` של Playwright היה מריץ בשקט את הבדיקות של סשן אחד מול הקוד של סשן אחר.

## להוסיף פקודה כבדה

1. מודדים אותה פעם אחת: זמן, CPU ו-RAM בשיא.
2. אם היא כבדה, מוסיפים שורה ל-`.claude/heavy-commands.txt`. כל שורה היא regex של JavaScript שנבדק מול כל פקודה בשורת Bash, אחרי שמסירים `cd x &&`, השמות משתנים כמו `FOO=1`, ו-`time`. כדאי לעגן את ה-regex בהתחלה (`^`), כדי ש-`grep "playwright test"` לא ייחסם.
3. בודקים:

```bash
echo '{"tool_input":{"command":"<הפקודה>"},"cwd":"'$PWD'"}' | node scripts/parallel/hook.mjs pretool; echo $?
```

קוד יציאה 2 אומר שהפקודה נחסמת. 0 אומר שהיא עוברת.

## לשנות את ספי העומס

ב-`.claude/parallel.json`:

- `maxLoad1`: ה-load המקסימלי. נמדד על 8 ליבות, ו-9 הוא בערך 1.1 לליבה.
- `minFreeMemMB`: הזיכרון הפנוי המינימלי. ב-Mac הוא נקרא מ-`kern.memorystatus_level`, כי `os.freemem()` מראה שם כמעט אפס גם כשהמחשב בסדר.
- `waitSeconds` ו-`recheckSeconds`: כמה זמן לחכות לעומס שירד, וכל כמה זמן לבדוק שוב.

אם סשנים מחכים כל הזמן, מעלים את `maxLoad1`. מצב העומס הנוכחי:

```bash
scripts/heavy --status
```

## נעילה תקועה

`scripts/heavy --status` מראה מי מחזיק את הנעילה ומוחק אותה אם התהליך כבר מת.

אם התהליך חי אבל תקוע, עוצרים אותו (`kill <pid>`), והנעילה משתחררת. אם זה לא עוזר, מוחקים אותה ידנית:

```bash
rm -rf "$(git rev-parse --git-common-dir)/claude-parallel/heavy.lock"
```

## לכבות את האכיפה זמנית

יש שתי דרכים:

- **לכל הסשנים, בלי restart:**

  ```bash
  touch "$(git rev-parse --git-common-dir)/claude-parallel/off"
  ```

  מחזירים עם `rm` של אותו קובץ.
- **לסשן אחד:** מגדירים `CLAUDE_PARALLEL_OFF=1` בסביבה שבה Claude Code רץ, למשל `"env": { "CLAUDE_PARALLEL_OFF": "1" }` ב-`.claude/settings.local.json`, ופותחים את הסשן מחדש.

הכיבוי משבית רק את החסימה. `scripts/heavy` עצמו ממשיך לנעול ולבדוק עומס.

## מגבלות

- **רק מה שמופיע ברשימה נתפס.** פקודה כבדה שנכתבה בצורה שה-regex לא מכיר תרוץ בלי נעילה.
- **ה-hooks נטענים רק בסשנים שנפתחו על `web/`.** סשן שנפתח על תיקיית האב `remember_07102026` לא רואה אותם.
- **בדיקות ה-e2e רגישות לעומס.** `panel.spec` דוגם פריימים אמיתיים, וכשה-load גבוה (סביב 8) הוא נכשל גם על קוד תקין. אם בדיקה כזו נכשלת, בודקים קודם את `scripts/heavy --status`.
- **הנעילה מסדרת את העבודה הכבדה בתור.** בילדים לא ירוצו מהר יותר, אבל הם לא יחנקו את המחשב.
