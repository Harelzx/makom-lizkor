# בדיקות ופריסה — מקום לזכור

המדיניות הזו מיישמת את מחקר 9.10.2026 שהראל אישר. היא מחליפה את הדרישה ההיסטורית לשתי חבילות דפדפן מלאות, פיתוח וסופי, בכל תיקון. גבולות פרטיות, הרשאות ופרסום לציבור לא משתנים.

## המסלול בפועל

1. `ci.yml` משווה את השינוי לבסיס קדמון שיש לו דוח מלא מאומת. בסיס חסר או ראיה לא תקפה מחייבים מלא. ב־PR נבדק המיזוג המוצע, אך דוח PR אינו אישור לפריסה.
2. תיעוד קיים בלבד: דוח קצר ללא פריסה. קובץ חדש/מחוק/ששמו השתנה, קובץ לא מוכר, תלויות, תשתית או לוגיקת מוצר: מלא.
3. רק `form-flower.tsx`, שינוי קיים באיורי `public/art/` וסגנונות `src/index.css` נמצאים ברשימת ההיתר לתצוגה. הסגנונות הגלובליים מפעילים קבוצת בדיקות רחבה. `add-place.tsx`, ה־store, API ו־legal.ts אינם מסלול תצוגה מהיר.
4. בכל שינוי קוד נשארות בדיקות טיפוסים, lint, פורמט, סקריפטים, Worker, לקוח, בנייה ובדיקת התוכן שלא אמור להיכלל בבנייה. חמש בדיקות WebKit בנייד רצות עם seed; בדיקות שרת הפיתוח ממוקדות כשנוגעים בהגדרותיו או כשאין בסיס.
5. מסלול מלא: חבילת Chromium בבילד הסופי מתחלקת לשתי מכונות עם worker אחד ומאגר דמה נפרד בכל אחת. בדיקת FPS נפרדת; בדיקת אנימציית הלוח וכותרות האבטחה נשארות בחבילה. איחוד התוצאות דורש כיסוי מלא ללא כפילויות, למעט seed בכל חלק.
6. מסלול תצוגה: 15 תרחישי ליבה (12 זרימות ושלוש בדיקות בילד סופי) וקבוצות מושפעות. לאחר הצלחה staging יכולה להתעדכן; `regression.yml` משלימה את החבילה המלאה באותו SHA ברקע. כישלון שם חוסם שחרור לציבור.
7. `ready` רצה גם בכשל ומסרבת לתוצאה חסרה, מבוטלת או מדולגת שלא תוכננה. הדוח נושא גרסה, ריצה, ניסיון, גרסת מדיניות ומסלול.
8. staging בודקת את דוח המוכנות ואת מקורו לפני שימוש בסודות. תיעוד אינו פורס. מועמד ישן לא דורס main שיש בו קוד חדש. הפריסות עצמן נשארות סדרתיות וכל תשע בדיקות הענן נשמרות.
9. release דורשת גם דוח מלא מאותו SHA, בנוסף ל־CI, לראיות staging ולכל תנאי ההשקה הקיימים. דוח של ריצה ישנה לאחר rerun אינו מתקבל. אין production credentials חדשים.

## פקודות מקומיות

- רשימה ללא פתיחת דפדפן: `node scripts/ci-browser.mjs list core`, או `list full 1/2`.
- בדיקות ממוקדות בעת פיתוח: `scripts/heavy npm run e2e:prod -- e2e/<file>.spec.ts -g '<scenario>'`.
- ליבה: `scripts/heavy node scripts/ci-browser.mjs run core`.
- נייד: `scripts/heavy node scripts/ci-browser.mjs run webkit`.
- מלא, כשנדרש מקומית: `scripts/heavy node scripts/ci-browser.mjs run full`.
- כל הדפדפנים לנגישות: `scripts/heavy node scripts/ci-browser.mjs run compatibility`.
- סקריפטים ומדיניות: `npm run test:scripts`.

כל הפקודות המקומיות הכבדות תחת `scripts/heavy`. אין להפעיל שני חלקי בדיקות במקביל על אותו Mac/checkout; החלוקה המקבילית מיועדת למכונות GitHub נפרדות. אין צורך בחבילה מלאה מקומית וגם בענן לכל שינוי קטן. כשל מצדיק קריאת הראיה ותיקון ממוקד, לא הגדלה גורפת של timeouts או ניסיון חוזר אוטומטי.

## ראיות וזמנים

`ci-results/` מחזיקה את רשימת התרחישים שתוכננו, תוצאת Playwright ו־receipt רק לאחר התאמה מלאה ו־pass בניסיון הראשון. דילוג, flaky pass, חריגת זמן ושגיאת runner אינם הצלחה. GitHub שומר תוצאות ו־traces לכשלים שבעה ימים, ודוחות אישור קטנים 90 יום. כל חלק מדווח זמן כולל ואת התרחישים הארוכים.

`compatibility.yml` מופעלת שבועית או ידנית, ומדלגת על SHA שכבר עבר בה. אין פריסה או סודות. בדיקות WebKit אינן תחליף לבדיקת האייפון הפיזי, ובדיקת GPS מדומה אינה הוכחת הרשאת GPS במכשיר.

יעדי המחקר (10–15 דקות לתצוגה מוכרת, 20–25 דקות לחלק הדפדפן המלא) הם יעדים למדידה. שינוי רחב בסגנונות עשוי לקחת יותר. שתי מכונות מקצרות המתנה, לא בהכרח דקות לחיוב; אין רכישת runner או שינוי תקציב.

הגבלות הזמן ראשוניות ושמרניות: חבילת full/core עד 35 דקות, WebKit עד עשר ודגימת dev עד חמש; מגבלת job כוללת מרווח להכנה ולהעלאת ראיות. אין הארכות אוטומטיות.

## תחזוקה

- שינוי משמעות במסלול מחייב עדכון `ci-plan.mjs`, מדיניות ה־CI ובדיקותיה, והגנת release יחד.
- מזהי `@core-*` ו־`@phone` בוחרים תרחישים קיימים. שינוי בחירה חייב לעבור בדיקת הרשימות והאיחוד; אין למחוק תרחיש בגלל שהוא איטי.
- כל בדיקה חדשה נכנסת לחבילה המלאה כברירת מחדל. רק קובצי תצוגה ידועים זכאים למסלול המוקדם; ברירת המחדל נשארת מלא.
- אין שיתוף build בין Cloudflare staging לייצור: סביבת Cloudflare נבחרת בזמן הבנייה.
- פריסת staging מתחילה מאירוע GitHub, ולא מבדיקת המעקב של הסוכן. אין צורך בשרת webhook נוסף.
- את מוקדי הזמן הבאים משפרים לפי הדוחות: tracking, reports, submission-recovery ונגישות. אין החלפת מפה ב־mock בבדיקה שמטרתה המפה. לא מוסיפים cache או משנים traces ללא מדידה שמצדיקה זאת.
- לפני פרסום לציבור נשארים אישורי התוכן, הזהות, התשתית והפרטיות הנדרשים; `RETENTION.verified` ו־`MAILBOX.verified` אינם משתנים בגלל CI.
